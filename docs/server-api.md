# სერვერის API

აპის საბაზო URL მითითებულია `src/config.ts`-ში. სერვერის დოკუმენტაციის მიხედვით, აპი იყენებს `/api/v1` API-ს. ყველა მოთხოვნას აქვს `Content-Type: application/json` და `Accept: application/json` სათაურები; წარმატებისას მოსალოდნელია HTTP `2xx`. მოთხოვნებს აქვს 20 წამიანი timeout.

## მოწყობილობის რეგისტრაცია

`POST /api/v1/devices/`

მდებარეობის გაზიარების სტატუსის ან კოორდინატების გაგზავნამდე აპი მოწყობილობას არეგისტრირებს. სერვერზე უკვე არსებული `device_id` ხელახლა გაგზავნისას მოწყობილობის `last_seen_at` ახლდება.

```json
{
  "device_id": "installation-uuid",
  "push_token": "FCM_DEVICE_TOKEN",
  "platform": "android",
  "language": "ka",
  "app_version": "1.0.0"
}
```

`push_token` იგზავნება, როცა შეტყობინებების ნებართვა ჩართულია და FCM ტოკენი ხელმისაწვდომია.

## ლოკაციის მდგომარეობის წაკითხვა

`GET /api/v1/location/<device_id>/`

აბრუნებს მოწყობილობის გაზიარების მდგომარეობას, ბოლო შენახულ კოორდინატებს და დროებს: `recorded_at` არის GPS ლოკაციის დაფიქსირების დრო, ხოლო `location_updated_at` — სერვერზე ლოკაციის ბოლოს შენახვის UTC დრო. კოორდინატები და დროები `null` იქნება, სანამ სერვერი ლოკაციას არ მიიღებს.

## ლოკაციის გაზიარების მართვა

`PATCH /api/v1/location/<device_id>/`

```json
{
  "location_sharing_enabled": true
}
```

`device_id` URL-ის ნაწილად იგზავნება. ახალი მოწყობილობისთვის გაზიარება გამორთულია; ჩართვა/გამორთვის მოთხოვნა მხოლოდ მოწყობილობის რეგისტრაციის შემდეგ გაიგზავნება. მდგომარეობის ცვლილების დროს სერვერი თავად ინახავს. ახალი backend-ის მიხედვით, `false` გაზიარებას თიშავს და ბოლო კოორდინატებს ტოვებს.

აპი ჩამრთველის გამორთვისას აგზავნის `PATCH false` მოთხოვნას. ახალი backend ამით გაზიარებას თიშავს და ბოლო შენახულ კოორდინატებს ტოვებს.

## ლოკაციის გაგზავნა

`POST /api/v1/location/<device_id>/`

```json
{
  "latitude": 41.7151,
  "longitude": 44.8271,
  "accuracy": 12.5,
  "recorded_at": "2026-11-04T12:00:00.000Z"
}
```

`latitude` და `longitude` სავალდებულოა; `accuracy` და `recorded_at` არჩევითია. აპი `recorded_at`-ს აგზავნის ISO 8601 დროით და `accuracy`-ს გამოტოვებს, თუ მნიშვნელობა უცნობია. წარმატებული პასუხი შეიცავს `location_updated_at`-ს, რომელსაც სერვერი ადგენს ლოკაციის შენახვისას; აპი ამ დროს წარმატების შეტყობინებაში აჩვენებს. ამგვარად GPS-ის დაფიქსირების დრო (`recorded_at`) და სერვერზე ბოლო განახლების დრო (`location_updated_at`) ცალ-ცალკე ინახება. `device_id` წინასწარ უნდა იყოს რეგისტრირებული `POST /api/v1/devices/`-ით; თუ მოწყობილობა არ არსებობს, პასუხია `404`. გაზიარების გამორთულ მდგომარეობაში POST მოთხოვნა `403`-ით სრულდება.

## ლოკაციის მონაცემების წაშლა

`DELETE /api/v1/location/<device_id>/` ლოკაციის გაზიარებას გამორთავს და ბოლო კოორდინატებს წაშლის. აპის პარამეტრის ჩამრთველი `PATCH`-ს იყენებს; `DELETE` ცალკე, მომხმარებლის მიერ მოთხოვნილი წაშლის მოქმედებისთვისაა.

## Push შეტყობინებები

სერვერმა შეტყობინება უნდა გაგზავნოს Firebase Admin SDK-ით ან FCM HTTP v1 API-ით მოწყობილობის `push_token`-ზე. FCM service account-ის კერძო გასაღები შეინახეთ მხოლოდ სერვერზე.
